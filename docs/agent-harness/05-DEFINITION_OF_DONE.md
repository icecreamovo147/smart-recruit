## 1. 每个任务的完成标准

每个任务必须同时满足以下所有条件才能标记为"已完成"：

### 1.1 代码实现

- [ ] 所有计划的功能代码已编写完成
- [ ] 无 `TODO`、`FIXME`、`HACK` 等未完成标记残留
- [ ] 无调试代码（`console.log`、`fmt.Println` 等，日志正常输出除外）
- [ ] 无被注释掉的代码块
- [ ] 新增代码有合理的注释（关键逻辑、复杂算法）

### 1.2 类型与构建

- [ ] 前端：`vue-tsc --noEmit` 通过（零类型错误）
- [ ] 前端：`vite build` 通过（零构建错误）
- [ ] 后端：`go vet ./...` 通过（零警告）
- [ ] 后端：`go build ./...` 通过（零编译错误）

### 1.3 测试

- [ ] 后端：`go test ./...` 全部通过
- [ ] 前端：`vitest run` 全部通过（如有测试）
- [ ] 新增代码有对应的测试覆盖（关键逻辑、边界条件）
- [ ] 现有测试无退化（未通过测试数量不增加）

### 1.4 权限

- [ ] 新增接口有权限常量定义
- [ ] 新增路由有 `meta.perm` 声明
- [ ] 权限校验逻辑已实现（管理员/普通用户区分）
- [ ] 数据权限已过滤（HR 只看到自己的数据）

### 1.5 安全

- [ ] API Key / 密钥不在任何响应中明文返回
- [ ] API Key / 密钥不在日志中打印
- [ ] API Key / 密钥不在前端 localStorage 存储
- [ ] 敏感数据已脱敏（手机号、身份证、简历正文）
- [ ] 无 SQL 注入风险（使用参数化查询）
- [ ] 文件上传有类型和大小校验

### 1.6 架构合规

- [ ] 未修改任务「禁止修改的文件」清单中的文件
- [ ] 未破坏现有路由 / 页面 / gRPC 方法
- [ ] 未修改已有数据库表结构（仅 ADD COLUMN）
- [ ] 新增 migration 文件版本号连续
- [ ] 未破坏 ADK / Legacy 双运行时逻辑

### 1.7 文档

- [ ] 如涉及新接口：接口文档已更新（代码注释 + Swagger 注释）
- [ ] 如涉及 configuration：配置文件已有示例和说明
- [ ] 如涉及 migration：迁移说明已记录
- [ ] 如涉及 ADR：ADR 文档已写入 `decisions/`
- [ ] README 相关章节已更新（如有重大变更）

### 1.8 任务管理

- [ ] 任务文件已更新完成日期与验证结果
- [ ] TRACEABILITY_MATRIX 中对应条目已更新状态
- [ ] 变更摘要已输出（修改文件清单 + 变更原因）
- [ ] 所有必须运行的测试命令已执行并全部通过

## 2. 简化验收流程

```
实现代码
  │
  ├─ 类型检查 / 构建通过？
  │   └─ 否 → 修复
  │
  ├─ 测试全部通过？
  │   └─ 否 → 修复或触发停止条件 S-5
  │
  ├─ 权限/安全检查通过？
  │   └─ 否 → 修复或触发停止条件
  │
  ├─ 架构合规？
  │   └─ 否 → 修复或触发停止条件
  │
  └─ 文档更新完成？
      └─ 是 → 标记 Done
```

---

## 3. 任务状态流转

```
pending → in_progress → reviewing → done
                           │
                           └→ blocked（需注明阻塞原因与解除条件）
```
