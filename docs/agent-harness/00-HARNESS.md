# 00-HARNESS — Agent 平台能力补齐工程约束总则

> 版本：v1.0
> 创建日期：2026-06-26
> 依据文档：`docs/智能招聘Agent平台能力缺陷调研报告.md`

---

## 1. 本 Harness 的目的

为智能招聘系统从「招聘业务系统 + 嵌入式 AI 助手」向「具备完整配置、工具、知识、可观测性能力的 Agent 平台」演进建立**工程约束体系**。

核心职责：
- 防止范围漂移：每个任务有明确边界
- 防止架构破坏：护栏规则明确不可逾越的红线
- 防止重复实现：缺陷追踪矩阵确保每个缺陷只做一次
- 确保可验收：Definition of Done + Review Checklist + 测试命令

---

## 2. 当前项目现状

| 维度 | 现状 |
|------|------|
| 架构 | Go Gin (Web 网关) + Go gRPC (Logic 服务) + Vue 3 三端前端 |
| AI 内核 | CloudWeGo Eino + ADK Agent，双运行时 (adk / legacy)，14 个硬编码 HR 工具 |
| 配置方式 | 环境变量 / YAML 配置文件，无可视化配置入口 |
| 可观测性 | AIToolTrace 落库但前端零展示，ThirdPartyUsageLog Token 估算 |
| 安全 | RBAC 完整，速率限制，审计日志；但 API Key 明文，无脱敏 |
| 扩展性 | 工具全部硬编码 Go，无 MCP / Skills / RAG |

## 3. 后续开发的总约束

### 3.1 允许做什么

- 新增前端页面、路由、组件（需遵循 Element Plus 风格）
- 新增 gRPC 服务、Proto message、RPC 方法
- 新增数据库 migration（版本号连续）
- 新增后端 repository / service / handler
- 新增中间件（需适配已有中间件链）
- 新增配置项（通过 config.yaml + 环境变量）
- 新增 Go 依赖（需 ADR 说明原因）
- 新增前端 npm 依赖（需评审必要性）
- 运行测试、构建验证、lint 检查

### 3.2 禁止做什么

- **禁止修改现有业务功能代码**（岗位、投递、面试、Offer、通知、协作等），除非任务明确列出
- **禁止重写 ADK / Legacy 双运行时逻辑**，除非 M6 阶段任务明确要求迁移
- **禁止修改现有数据库表结构**，只能 ADD COLUMN 或新增表
- **禁止修改现有 RBAC 权限常量含义**（`PERM.*` 只能新增不能改语义）
- **禁止删除或重命名已有的 gRPC 方法**
- **禁止向前端返回明文 API Key / 密钥**
- **禁止在日志中打印敏感字段**（API Key、密码、简历正文）
- **禁止在没有 ADR 的情况下引入新的基础设施依赖**（如新数据库、消息队列、向量库）
- **禁止未经任务文档就开始写代码**

### 3.3 任务铁律

1. 没有任务文档 → 不允许开发
2. 没有测试命令 → 不允许标记完成
3. 没有验收结果 → 不允许进入下一任务
4. 涉及数据库/权限/API Key/Prompt/MCP/RAG → 必须先写 ADR
5. 每个任务必须可独立验收

## 4. Agent 执行任务规范

### 4.1 执行任务前必须读取

| 序号 | 文件 | 目的 |
|------|------|------|
| 1 | `00-HARNESS.md` | 理解总约束 |
| 2 | 目标任务文件 (`tasks/xxx.md`) | 理解任务范围 |
| 3 | `03-ARCHITECTURE_GUARDRAILS.md` | 确认不触犯护栏 |
| 4 | 目标模块现有代码 | 理解现状，避免破坏 |
| 5 | `01-ROADMAP.md` | 确认任务处于正确阶段 |
| 6 | `05-DEFINITION_OF_DONE.md` | 确认完成标准 |

### 4.2 执行任务后必须输出

1. 变更摘要（修改了哪些文件、变更原因）
2. 验证结果（测试命令输出截图或摘要）
3. 任务状态更新（pending → in_progress → done）
4. 如涉及 ADR：ADR 文档
5. 如涉及 migration：migration 版本号 + 文件名
6. 如涉及接口变更：接口变更清单
7. 任务完成标记：在任务文件中写入完成日期与验证结果

### 4.3 任务完成前必须运行

1. 前端类型检查 (`vue-tsc --noEmit`)
2. 前端构建 (`vite build`)
3. 后端测试 (`go test ./...`)
4. 如有 migration：migration test
5. 权限校验检查（如涉及权限变更）
6. 敏感信息检查（如涉及 API Key / 简历）

## 5. 停止条件

以下任一条件触发时，必须**立即停止并请求人工确认**：

| 编号 | 停止条件 |
|------|----------|
| S-1 | 任务描述与代码实际情况不一致，无法按计划执行 |
| S-2 | 需要修改任务范围外（`禁止修改的文件`）的文件 |
| S-3 | 需要新增数据库表但没有 migration 方案 |
| S-4 | 需要引入新 Go/npm 依赖但没有在 ADR 中说明原因 |
| S-5 | 测试失败且无法在当前任务范围内修复 |
| S-6 | 发现变更会影响现有招聘业务流程（岗位/投递/面试/Offer） |
| S-7 | 发现需要修改已有 RBAC 权限常量语义 |
| S-8 | 发现需要删除或重命名已有 gRPC 方法 |
| S-9 | 发现需要在日志中打印敏感字段 |
| S-10 | 发现 API Key 或密钥可能被明文返回前端 |
| S-11 | 发现任务与其他未完成任务存在冲突 |
| S-12 | 发现对 ADK/Legacy 双运行时的影响未在任务中评估 |

## 6. ADR 决策要求

以下场景**必须先创建 ADR**（存入 `docs/agent-harness/decisions/`）：

- 引入新依赖（Go module 或 npm package）
- 新增数据库表 / 字段
- 新增 gRPC 服务 / 修改 Proto
- 引入新基础设施（向量库、MCP SDK 等）
- 架构模式选择（如前端组件拆分方式）
- API Key 存储方案变更
- 脱敏方案选择
- Prompt 管理方案

ADR 命名：`YYYYMMDD-简短描述.md`

---

## 7. 沟通规范

- 任务执行过程中不得修改 Harness 文档（除非任务明确要求）
- 如需更新缺陷调研报告，必须先说明原因
- 任务执行结果需在对话中明确报告完成状态
