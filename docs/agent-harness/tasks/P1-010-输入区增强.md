# 任务编号：P1-010

## 1. 任务目标

增强 HR 端聊天页输入区，在输入框上方新增功能开关组：工具调用开关、知识库检索开关（占位，M5 阶段实际接入）、数据源查询开关。补充会话与岗位/候选人/数据源的绑定关系。

## 2. 对应缺陷

- **缺陷 11**：输入区功能过弱，无工具/知识库/数据源开关
- **缺陷 11**（关联）：会话与岗位/候选人/数据源无绑定关系

## 3. 前置条件

- P0-002 完成（状态栏就绪，开关状态可在状态栏展示）
- M2 阶段完成（模型选择器在 P0-006 中实现，本任务补充开关组）

## 4. 允许修改的文件

- `hr-frontend/src/views/hr/AIChatView.vue`
- `hr-frontend/src/api/ai.ts`（如开关状态需随请求发送）
- `hr-frontend/src/types/ai.ts`（如新增参数类型）

## 5. 禁止修改的文件

- `logic-grpc-service/` 下所有文件
- `web-gin-service/` 下所有文件
- 其他前端页面

## 6. 实现步骤

1. **开关组 UI**：在输入框上方新增一行开关组
   - 「🛠 工具调用」`el-switch`，默认打开
   - 「📚 知识库检索」`el-switch`，默认关闭（M5 阶段实际生效，本期仅 UI 占位 + `disabled`）
   - 「🗄 数据源查询」`el-switch`，默认打开
   - 使用 `el-tooltip` 提供每个开关的说明文字
2. **会话绑定关系**：在聊天页顶部状态栏增加
   - 「关联岗位」选择器（可选，下拉搜索岗位）
   - 「关联候选人」选择器（可选，下拉搜索候选人）
   - 绑定后 SSE 请求携带 `job_id` / `application_id`
3. **开关状态传递**：在 SSE 请求中附带开关状态（如 `enable_tools: true/false`）
4. 样式与已有对话 UI 协调，不挤压消息区域

## 7. 数据库变更

不涉及

## 8. 接口变更

- SSE 请求参数可能新增 `enable_tools` / `enable_knowledge_base` / `job_id` / `application_id` 字段（需与后端协商标记 optional）

## 9. 前端变更

- `AIChatView.vue`：新增开关组 + 关联岗位/候选人选择器
- `api/ai.ts`：请求参数扩展
- `types/ai.ts`：类型扩展

## 10. 权限与安全要求

- 关联岗位/候选人仅限当前 HR 数据范围
- 开关状态不绕过权限（后端仍需校验）
