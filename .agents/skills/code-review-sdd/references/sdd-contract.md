# Code Review SDD Contract

## Purpose

`code-review-sdd.md` is an agent-executable repair plan generated by `code-review-leader` when actionable findings exist. Another agent using `code-review-sdd` should be able to execute it without guessing evidence, scope, acceptance criteria, or verification commands.

## Source of truth

1. The fenced `code-review-sdd-manifest` JSON block inside the Markdown plan is the machine-readable contract.
2. The surrounding Markdown is human-readable context and must stay consistent with the manifest.
3. Keep the plan file read-only during repair. Record progress in `.code-review-sdd/fix-runs/`.

## Task rules

- Task IDs use `CR-NNN`.
- Finding IDs use `F-NNN` and must be referenced by at least one task when open.
- Priorities: `P0`, `P1`, `P2`, `P3`.
- Order execution by dependency closure, then priority, then task ID.
- `allowed_paths` and `excluded_paths` must be relative repository paths. Reject
  non-string values, URI schemes such as `file:` or `https:`, C0/DEL control
  characters, repository-root aliases (`.` or `./`), POSIX and Windows
  absolute/drive paths, home-directory paths, parent traversal after
  normalization, and protected repair metadata under `.git/` or
  `.code-review-sdd/`. Also reject wildcard-only root scopes such as `*`, `**`,
  `*/*`, or `**/*`, plus root glob segments without an alphanumeric static
  prefix (for example `.git*`, `[.]git`, `{.git,src}`, or `**/.git`). Focused
  module globs such as `src/**/*.ts` and `smart-recruit-*/**`, plus static hidden
  directories such as `.agents/**`, remain valid.
- Empty `allowed_paths` is invalid for execution; stop with `SCOPE_GAP` and ask for an explicit path list.
- Finding status is trimmed, normalized to uppercase, and must be `OPEN` or
  `CLOSED`; omitted status defaults to `OPEN`. Every `OPEN` finding must be
  referenced by at least one task. `CLOSED` findings may remain as historical
  context without a repair task.
- Prefer focused regression tests for behavioral findings.
- Set `human_confirmation_required: true` for public API, schema/migration, shared auth/security policy, lockfile/global config, or destructive operations.

## No-action canonical state

When the latest Code Review Leader result has no actionable findings, the
canonical `.code-review-sdd/code-review-sdd.md` contains the same fenced
manifest with:

```json
{
  "schema_version": 1,
  "no_action": true,
  "review": {},
  "findings": [],
  "strategy": [],
  "tasks": []
}
```

This is the only valid zero-task manifest. It is authoritative and invalidates
older actionable plans. The parser returns `no_action: true` and
`task_count: 0`; discovery must stop and must not fall back to timestamped SDD
files. A no-action manifest containing findings or tasks is invalid.

## Default discovery

1. User-specified path
2. `.code-review-sdd/code-review-sdd.md`; a valid no-action marker stops discovery
3. Unique latest match under `.code-review-sdd/` for `*code-review-sdd.md` or `*-sdd.md`

## Final statuses

| Status | Meaning |
|---|---|
| `REPAIR_COMPLETE_PENDING_REREVIEW` | All selected tasks passed or already resolved; recommend fresh review |
| `REPAIR_PARTIAL` | Some tasks passed; others blocked/stale/awaiting confirmation |
| `REPAIR_BLOCKED` | No further ready tasks; blockers remain |
| `REPAIR_ABORTED` | Run stopped due to unsafe state, plan mismatch, or user abort |
